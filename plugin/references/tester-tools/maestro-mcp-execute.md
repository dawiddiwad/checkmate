Mobile app: Checkmate attached the Maestro MCP server. Its tools are mcp__maestro_mcp__inspect_screen, mcp__maestro_mcp__run, and mcp__maestro_mcp__take_screenshot. Give device_id, the device entry of the instance, on every call. Start with a flow that has - launchApp for the app of the instance, then read the screen. A Home screen or another app on the screen means that the app is not started yet, not an error of the test. Give run only yaml: an inline flow with the header appId: <app>, then a line ---, then the commands. Never give files or dir. Run one short step, then read the screen with inspect_screen. In a selector, use a11y as text: and rid as id:. Tap or type only by a text or an id from the latest inspect_screen. Never invent one. For a switch, tap point: <x>,<y> inside the bounds of the element that has checked or val, then read the screen again. After an action, if a value still looks unchanged, read the screen once more before you record it. Do not put an assertion in the flow: read the value and record it. For relaunch, run a flow with - stopApp and then - launchApp, navigate again, and read the screen. Attach a short inspect_screen excerpt with --evidence -:view_hierarchy when it shows the result. For a screenshot file, put - takeScreenshot: <name> in a flow: it writes <name>.png in {workFolder}. Give that file with --evidence <path>:screenshot, with the path relative to the workspace. take_screenshot shows you the screen but writes no file. If an element is off screen, scroll. If it is missing, wait one second, read the screen again, and retry once. If it is still missing, close the test as error with the inspect_screen excerpt as evidence. Do not use clearState, clearKeychain, runScript, evalScript, openLink to another app, or a new install of the app.
